## 1. Прыгающий layout кнопок +/- при выборе количества

**Файл:** `src/shared/ui/game/keyboards.ts` — `buildSelectKeyboard`

**Проблема:** кнопки `-` и `+` рендерятся условно. Когда одна из них недоступна, оставшаяся висит слева одиноко, и layout визуально сдвигается между шагами.

**Как воспроизвести:** начать ход, дойти до этапа выбора количества карт. При значении `1` кнопка `-` отсутствует — `+` одна слева. Нажать `+` — появляются обе кнопки, layout прыгает.

## 2. Два кодпаса проверки active-player в back-хендлере

**Файл:** `src/modules/game/handlers.ts` — `gameTurnBackCallbackHandler`

**Проблема:** ветки `p#` и `c#` используют `resolveActivePlayerForGame` (явный `game.activePlayer.id !== me.id` → `STALE_GAME_MESSAGE`), а ветки `count/colors/suits` — `resolveTurnContext`, который полагается на `validateTurnMeta` с выбросом `InvalidGameFlowError`. Оба пути работают, но это два разных механизма с разной формой сообщений об ошибке в случае расхождений.

**Что сделать:** унифицировать проверку active-player — вероятно, через расширение `resolveTurnContext` или вызов `resolveActivePlayerForGame` перед ним во всех ветках.

## 4. Кнопка «Отправить сообщение хода» оставляет зомби-сообщение

**Файл:** `src/entities/game/services/game-notifications.service.ts` — `sendFirstMessage`

**Проблема:** `sendFirstMessage` использует `BOT.api.sendMessage` — отправляет **новое** сообщение хода активному игроку, не удаляя старое. У игрока остаются два сообщения с активными inline-кнопками выбора цели. Оба рабочие — нажатие на устаревшее может продублировать действие или нарушить стейт хода.

**Что сделать:** отслеживать `message_id` последнего сообщения хода в `game.utils` и редактировать его через `BOT.api.editMessageText` вместо создания нового; либо удалять старое перед отправкой нового.

## 5. `ensureActivePlayerHasCards` тихо сдвигает ход при ресенде

**Файл:** `src/entities/game/services/game-notifications.service.ts:29` — `sendFirstMessage`

**Проблема:** при нажатии «Отправить сообщение хода» вызывается `game.ensureActivePlayerHasCards()`, который может сдвинуть ход если активный игрок остался без карт. Сообщение хода полетит уже **следующему** активному игроку без какого-либо уведомления остальных участников о смене хода.

**Что сделать:** перед вызовом `sendFirstMessage` проверять, что у активного игрока есть карты; если нет — показывать владельцу предупреждение вместо тихого сдвига.
